## 1.4 修复内容

这一版解决的是**真机上实际出现的两个问题**：点开就闪退、桌面图标像皮包公司。

### 一、启动闪退（真正的根因）

前两版都以为闪退是主题 API 兼容问题，其实不是。真正的根因查出来了：

`activity_main.xml` 里的搜索框 `TextInputLayout` 通过 `boxStrokeColor`
引用了 `@color/field_stroke`。这个文件在 `res/color/` 下，是一个
ColorStateList 选择器，当时内容是这样的：

```xml
<selector xmlns:android="http://schemas.android.com/apk/res/android">
    <item android:color="@color/app_primary" android:state_focused="true" />
    <item android:color="@color/app_line"    android:state_focused="false" />
</selector>
```

**两项都带状态条件，缺少不带任何状态的默认项。** 控件在既不聚焦、又不处于
「明确失焦」的中间状态时，取色匹配不到任何一项，系统直接抛：

```
android.content.res.Resources$NotFoundException:
    Can't find ColorStateList from drawable resource ID #0x7f05006c
```

这个异常发生在 `setContentView` 的布局 inflate 阶段，也就是
**Activity 还没创建完就抛了**，进程被系统直接杀掉 —— 表现为「点进去直接闪退」，
连错误提示都看不到。

修复：补上无状态默认项。

```xml
<selector xmlns:android="http://schemas.android.com/apk/res/android">
    <item android:color="@color/app_primary" android:state_focused="true" />
    <item android:color="@color/app_primary" android:state_hovered="true" />
    <item android:color="@color/app_line" />
</selector>
```

同时做了两件事防止同类问题再犯：

- `onCreate` 全程 try-catch，万一还有异常，会把堆栈直接显示在屏幕上，
  而不是让用户只看到「已停止运行」
- 新增 `ColorSelectorRegressionTest`，扫描所有 `res/color/` 选择器，
  强制要求必须带无状态默认项

### 二、定时刷新空指针（另一个真实崩溃点）

`refreshCodes()` 由每秒定时器调用，但里面直接用了 `adapter.notifyDataSetChanged()`，
没有判空。如果视图绑定中途失败（比如上面那个 inflate 异常被捕获后），
`adapter` 永远为 null，定时器每秒触发一次就崩一次。

修复：`refreshCodes()` 与 `updateQuickPanel()` 全部加判空；新增 `ready` 标志，
初始化未完成时定时器不启动。

### 三、图标重做

之前的图标虽然「存在」，但光栅化质量极差 —— **整张图只有 3 种颜色**，
就是一块蓝底加一个粗糙白色形状，肉眼看上去就是个没做完的占位图。

现在重做了图标：

- 设计：蓝色垂直渐变底 + 白色盾牌 + 盾内钥匙孔
- 用 8 倍超采样绘制后降采样，边缘平滑无锯齿
- 5 种密度 PNG 全覆盖：mdpi 48 / hdpi 72 / xhdpi 96 / xxhdpi 144 / xxxhdpi 192
- 方形与圆形两套
- 自适应图标的前景层与背景层也换成同源 PNG，保证 API 26+ 与旧设备观感一致
- 单张图标颜色层次从 3 种提升到 1400+ 种

新增 `图标内容不是粗糙色块` 测试，直接解码 PNG 统计颜色数，少于 16 种即判定失败。

### 四、位数显示逻辑修正

`groupCode()` 的注释与实现不符（注释说「非 6/8 位原样显示」，代码却是按 4 位分组）。
已统一为：6 位切 3+3，8 位切 4+4，其余按 4 位一组切分。

## 界面结构

界面分上下两块，比例约 **3 : 1**。

**上部（约 3/4）· 账户管理**

- 顶部标题栏：应用名 + 全局倒计时 + 「添加」按钮
- 搜索框：按名称、发行方或密钥过滤
- 工具条：导入 / 导出 / 排序
- 账户卡片列表：每张卡片显示名称、算法参数、大号验证码、剩余时间进度条、复制按钮
- 卡片右上角「⋮」可编辑、置顶、复制密钥、删除
- 点击卡片切换为「当前账户」，同步到下方快速区

**下部（约 1/4）· 快速验证码**

- 显示当前选中账户的名称与大号验证码
- 一键复制按钮
- 剩余时间进度条，剩余 5 秒内转为橙色提示

圆角统一控制在 6～10dp，克制不夸张。

## 功能

- TOTP 双因素验证码生成
- **位数不受限制**：1～18 位均可，7 位、9 位这类非标准位数同样正确输出
- 支持 SHA1 / SHA256 / SHA512 三种算法
- 支持自定义周期（5～300 秒）
- 支持 `otpauth://` 链接导入，自动识别算法、位数、周期
- 新增账户名称留空时，自动命名为「验证器一」「验证器二」……
- 支持剪贴板导入、文件导入、文件导出
- 账户搜索、置顶、重命名、编辑、复制密钥
- 验证码到期颜色提示

## 关于位数

旧版把位数写死成「6 位或 8 位」两种模式，传入 7 位会按 6 位计算，属于错误行为。
1.2 起改为通用公式 `10^digits`，1～18 位任意长度都按输入值真实计算。
上限取 18 是因为 `long` 能安全表示 `10^18`。

举例：输入 8 个 `E`，会先按 Base32 解码成二进制，正常算出对应位数的验证码，
不会因为不是标准位数就拒绝或算错。

## 关于权限

本应用**不申请任何 Android 权限**。导入导出使用系统文件选择器（SAF），
因此不需要存储权限。账户数据仅保存在本机应用私有目录。

## 测试

测试分两层。

### 第一层：算法与静态审计（只依赖 JDK）

```bash
bash tools/algorithm-tests/run.sh
```

共 135 项 + 1 套启动路径审计：

- `TotpTest`：RFC 6238 官方向量、多算法、多位数
- `UriTest`：otpauth 解析、中文编码、往返一致性
- `ImportTest`：混合格式导入、去重、边界情况
- `AnyDigitTest`：1～18 位任意位数的正确性验证
- `StartupAudit`：解析 APK 资源表，核对所有 id / 颜色 / 图形 / 样式 / 文案引用

### 第二层：Android 运行时测试（Robolectric，需要 Android SDK）

```bash
bash tools/setup-robolectric.sh          # 首次运行，拉取依赖
bash tools/algorithm-tests/run.sh --android
```

共 34 项，会把 Activity 真的创建出来跑一遍：

- `LaunchTest`：Activity 创建、完整生命周期、配置重建、关键控件绑定、图标质量
- `LayoutInflateTest`：三个布局全部真实 inflate，校验主题、颜色选择器、图形、样式
- `ColorSelectorRegressionTest`：颜色选择器必须有默认项（本次闪退的回归防护）
- `TotpRuntimeTest`：在真实 Android 运行时里验证 TOTP 与分组显示
- `DiagnoseTest`：初始化异常诊断，会把 `showFatal()` 捕获到的堆栈打印出来

这一层是这次真正查出问题的关键 —— 静态审计全绿，但 Activity 一跑就暴露了
`Resources$NotFoundException`。

> 注：Robolectric 需要约 150MB 的 `android-all` jar。国内直连
> `repo1.maven.org` 经常失败，`tools/setup-robolectric.sh` 会自动改用阿里云镜像
> 下载并配好离线仓库。
